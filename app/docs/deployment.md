# Самостоятельное развертывание

Этот способ публикует приложение в собственном Cloudflare Workers с D1 и Durable Objects. Вход в Higgsfield посетителям такого адреса не требуется. Действующий адрес `ai-university.higgsfield.app` обслуживается Higgsfield и при проверке возвращал HTTP 401 без входа в платформу.

Нужны аккаунт Cloudflare с возможностью создавать Workers, D1 и Durable Objects, Node.js 22 и Bun 1.4.2. Команды выполняются из `app/`. Используется опубликованный Wrangler 4.146.0. Секреты для текущего сценарного ведущего не требуются.

## 1. Установка и локальная проверка

```sh
git clone https://github.com/estatedsgn/ai-university.git
cd ai-university/app
bun install --frozen-lockfile
bun run build
bunx wrangler@4.146.0 d1 migrations apply ai-university-db --local --config wrangler.jsonc
bunx wrangler@4.146.0 dev --config wrangler.jsonc
```

Открой `http://localhost:8787`, создай комнату и проверь вход второго браузера по приглашению. В браузере разреши доступ к устройствам кнопкой «Подключить камеру и звук». Микрофон доступен после начала занятия в свой ход. Для первого теста удобны два устройства и наушники.

Vite dev не заменяет этот режим: API комнат требует Cloudflare Durable Objects, а анкета — D1. Локальные данные Wrangler находятся в `app/.wrangler/` и исключены из Git.

## 2. Создание базы и настройки

```sh
bunx wrangler@4.146.0 login
bunx wrangler@4.146.0 d1 create ai-university-db
```

Команда создания напечатает реальный `database_id`. В `wrangler.jsonc` замени только UUID-заглушку в существующей секции `d1_databases`; сохрани `binding: "DB"`, `database_name: "ai-university-db"` и `migrations_dir: "migrations"`. Если это имя базы уже занято в аккаунте, используй другое имя в конфигурации и последующих командах.

Для рабочего окружения поставь `vars.HF_ENV` в `"production"`. `APP_SLUG` можно оставить `"ai-university"`. При нескольких аккаунтах Cloudflare укажи нужный `account_id` в конфигурации.

В репозитории уже настроены:

- Worker entry `dist/server/server.js` и статические файлы `dist/client`.
- D1 binding `DB`.
- Durable Object binding `ROOMS` с классом `Rooms`.
- SQLite-миграция Durable Object с тегом `v1`, создающая класс `Rooms`.
- Флаг `nodejs_compat`.

Сохрани binding и имя класса: сервер использует их напрямую. `app.manifest.json` предназначен для Higgsfield; самостоятельный Wrangler читает `wrangler.jsonc`.

## 3. Миграции и публикация

Сначала примени SQL-миграции к выбранной удаленной D1 базе, затем опубликуй сборку:

```sh
bunx wrangler@4.146.0 d1 migrations apply ai-university-db --remote --config wrangler.jsonc
bun run build
bunx wrangler@4.146.0 deploy --config wrangler.jsonc
```

Миграция `0001_enrollment.sql` добавляет таблицы заявок и ограничений частоты; `0002_learning.sql` — серверные попытки и квоты, `0003_materials.sql` — приватные импортированные тесты. Миграции сохраняют существующие данные. Wrangler отслеживает примененные D1-миграции, повторный запуск применит только новые. Миграция класса `Rooms` выполняется при публикации Worker. Для следующих изменений добавляй новые миграции, сохраняя уже примененные файлы и теги.

Wrangler напечатает HTTPS-адрес Worker, обычно `https://ai-university.<твой-поддомен>.workers.dev`. Если Workers subdomain еще не настроен, заверши его настройку в Cloudflare. На этот адрес можно назначить собственный домен в панели Workers.

Проверь адрес в приватном окне браузера: страница должна открываться без входа в Higgsfield. Анкета и WebSocket должны обращаться к тому же origin. HTTPS нужен для камеры и микрофона вне localhost.

Для собственного домена обнови canonical и абсолютный адрес `og:image` в `src/routes/__root.tsx`, затем пересобери и опубликуй. Эти метаданные сейчас указывают на Higgsfield.

## 4. Проверка перед приглашением людей

- Открой страницу без авторизации; проверь отправку своей тестовой заявки.
- Создай комнату и открой приглашение на втором устройстве.
- Подними руку, начни занятие, включи микрофон в свой ход и передай слово.
- Пройди учебный модуль, затем обнови страницу и проверь сохранение прогресса в этом браузере.

Заявки доступны владельцу через D1 в панели Cloudflare; публичного API выгрузки нет. Не добавляй контактные данные и выгрузки базы в GitHub.

## Что остается ограниченным

Ведущий работает по сценариям, без генеративной модели и распознавания речи. Медиа передается напрямую между участниками по WebRTC; есть STUN, но нет TURN/SFU. Поэтому некоторые корпоративные и мобильные сети могут не пропускать звонок. Очередь хранится на сервере, а отключение микрофона выполняет штатный клиент; для принудительного контроля аудио на сервере потребуется SFU.

Прогресс модуля активного слушания остаётся в локальном хранилище браузера. Попытки карты знаний сохраняются в D1 и доступны через анонимную HttpOnly cookie этого браузера. Потеря cookie означает потерю доступа к попыткам; аккаунты, синхронизация между устройствами и автоматические рассылки пока не реализованы.

Математические задания и импорт готового JSON-теста доступны без ключей. Для генерации по тексту или разрешённой образовательной ссылке настрой серверные `OPENAI_API_KEY` и `MATERIAL_IMPORT_TOKEN`, как описано в [инструкции импорта](material-import.md). Платная генерация ограничена токеном организатора; не публикуй значения секретов в репозитории.
